# Byr 랜딩 카드 모션그래픽

## 1. 무엇을 만드는가 — 아트가 아니라 기능 설명

카드 영상은 **각 카드의 문구를 실제 제품 화면으로 설명해야 한다.** 추상 아트는 안 된다.

레퍼런스인 [phantom.com](https://phantom.com) 카드 영상을 실측한 결과:

| | phantom |
|---|---|
| 규격 | **1048×1400 (정확히 3:4)** |
| 길이 | 1.9 ~ 2.7초 |
| 내용 | **실제 앱 UI가 움직인다** — 폰 목업 안에서 상태 알약이 `Buy SOL → Buying → Bought 1.40 of SOL`로 전환. 다른 카드는 앱 아이콘 주위로 `Traders`·`Apps`·`Tokens` 라벨 칩이 날아든다 |
| 핵심 | 또렷한 UI와 **읽히는 글자** |

우리도 같은 원칙으로 간다. 재료는 `console-prototype`의 실제 화면과 카피다.

## 2. 왜 AI 영상이 아니라 코드인가

처음엔 higgsfield(Seedance 1.5 Pro)로 추상 배경 루프 12장을 만들었다가 전량 폐기했다. 이유:

1. **AI 영상 모델은 글자를 못 쓴다.** 프롬프트에 UI를 넣어도 뭉개진 가짜 한글이 나온다. 제품 설명 영상에서 이건 치명적이다.
2. **결과물이 내용과 무관했다.** 유리 오브제·입자·안개로는 "직무 프리셋 8종"이나 "승인 게이트"가 전달되지 않는다.
3. 부수적으로: 브랜드 색이 안 잡혀 카드별 보정이 필요했고(H 162~189로 산포), 모션이 문구 자리를 침범해 CSS 스크림까지 필요했다.

코드로 만들면 이 셋이 전부 사라진다. 한글이 선명하고, 내용이 정확하고, 색은 토큰 그대로다. 크레딧도 0.

**phantom도 AI로 만든 게 아니다.** 실제 UI 애셋으로 만든 모션그래픽이다.

## 3. 제작 방식 — `render(t)`

[scenes.html](scenes.html) 한 파일에 장면 12개가 들어 있다. 핵심은 **CSS 애니메이션을 쓰지 않는 것**이다.

```js
window.render = t => step(t)   // t ∈ [0,1)
```

`t`를 받아 상태를 직접 계산해 그린다. 이 방식의 이점:

- **프레임 캡처가 결정론적** — 몇 번을 돌려도 같은 프레임이 나온다
- **루프 이음매가 원천적으로 없다** — `t=0`과 `t=1`이 같도록 설계하면 끝. 사후 보정이 필요 없다
- 타이밍을 코드로 조정 → 재생성 비용 0

장면 호출:

```
scenes.html?scene=s1-1&w=1048&h=1400
```

### 헤드룸 규칙

카드 문구가 `padding: 48px`로 상단에 얹히므로([styles.css:209](../styles.css#L209)), 모든 장면은 **상단 430px을 비운다**(1400px 중). 규칙으로 두지 않고 `mkStage()`가 `top:430px; overflow:hidden` 무대를 깔아 구조적으로 강제한다. 덕분에 CSS 스크림이 필요 없다.

## 4. 장면 12개

### 카드 11장 — phantom 그래픽 문법 + UI 내용 유지

phantom 카드를 실측해 규칙 4가지를 뽑아 적용했다. **내용(UI)은 유지한다** — 카드 문구를 설명해야 하므로.

| | phantom 카드 | 이전 우리 | 현재 |
|---|---|---|---|
| 배경 | 채도 있는 브랜드 색 (라일락·크림·블랙) | 무채색 다크/라이트 2종 | **틸 램프 6단 + 청록 2단** |
| 주인공 | 1개, 거대하게, **프레임 밖으로 잘림** | 여러 개, 여백 두고 인셋 | **1개, 프레임 안에 온전히** |
| 대비 | 배경↔UI 고대비 | 다크 위 다크 | **고대비** |
| 길이·fps | 1.9~2.7초 · 30fps | 4~7초 · 25fps | **2.0~2.8초 · 30fps** |

> **phantom의 "잘림" 규칙은 채택하지 않는다 (2026-07-27 소이님 결정).**
> phantom은 주인공을 프레임 밖으로 흘려 크기를 과시하지만, 우리 카드는 **제품 UI를 설명**하는 것이라 잘린 컨트롤은 "미완성"으로 읽힌다.
> 무대 경계: x 0~1048 · y 430~1400, 좌우·하단 각 40px 여백. **어떤 t에서도 이 밖으로 나가는 요소가 없어야 한다** — 40프레임 전수 검사 기준 11장 × 2팔레트 = **넘침 0건**.
> 대가: 주인공 폭이 1228 → 968px(-21%)로 줄었고, 화면 점유율 진폭이 12~31%p → 1~26%p로 떨어졌다. 움직임을 **면적 변화가 아니라 내용 변화**(상태 전환·행 교체·목록 열림)로 만든다.

**길이를 2.0~2.8초로 어긋나게** 배분했다. 덱에 여러 장이 동시에 보이는데 전부 같은 길이면 동기화돼 화면이 맥동한다.

**카드 표시 크기 427×571 → 512×685 (2026-07-27).** phantom 실측은 427이었으나 1440 뷰포트에서 정확히 3장이 딱 차 넘치지도 딱 맞지도 않았다 — 스와이프가 생기지 않는 폭이다. 512면 2.5장이 보여 "더 있다"가 읽히고, 잘림 금지로 21% 줄어든 카드 안 UI 가독성도 되돌아온다. 영상 원본(1048×1400)은 그대로다 — 512×2 = 1024 < 1048이라 2배 화면에서도 선명하다.

**문구 가독성** — 배경이 밝아진 카드는 글씨색을 뒤집어야 한다. s1-1(`--t-90`)과 s3-2(`--c-point`)를 `card--light`(흰 글씨) → `card--dark`(검정)로 바꿨다. 브랜드 틸 위 흰 글씨는 3.1:1로 기준(4.5:1) 미달이다. 전 장 실측 **5.61~19.10 : 1** 통과.

**헤드룸을 구조로 강제한다.** 좌표를 조심하는 게 아니라 `mkStage()`가 `top:430px; overflow:hidden` 무대를 깔아 **문구 자리를 물리적으로 침범할 수 없게** 만든다. 실측에서 전 장 최악 프레임이 전부 0프레임(= 배경만 있는 상태)으로 나왔다 — 어느 프레임에서도 무언가가 위로 새어 나오지 않았다는 뜻이다.

**루프는 화면을 비워 닫지 않는다.** 프레임 밖 주차를 쓸 수 없으므로(잘림 금지) 등장·퇴장을 **경계 안에서** 처리한다 — 투명도, 중심 기준 축소(`0.988 → 1.0 → 0.988`, 커지는 방향은 쓰지 않는다), 높이 `0 → 열림 → 0`, 요소 내부 순차 등장. 상태값에 `(1−퇴장)`을 곱해 초기값으로 되감아 닫는다. 덕분에 0프레임 포스터가 빈 배경이 아니라 UI가 온전히 보이는 그림이 된다.

### 4.1 팔레트 — 모노톤 + 틸 (2026-07-28 확정)

**뼈대는 무채색 8단, 유채색은 틸 3단(`--t-45` `--t-62` `--t-78`)뿐이다.** phantom식(한 색상대를 명도 전 범위로 전개)이 아니라 Sana식(무채색 뼈대 + 극소량 액센트)이다.

라임(`#CBFC00`)을 검토했다가 폐기했다. 근거:

| 색 | 상대휘도 | 흰 글씨 | 검정 글씨 |
|---|---|---|---|
| 라임 `#CBFC00` | **82%** | 1.20 | 17.46 |
| 틸 `#0EA5A0` | 30% | 3.04 | 6.91 |

라임은 거의 흰색이라 (a) 흰 면 위에서 형태가 사라지고(1.20:1 — 버튼·심볼마크에 검정 인셋 링이 필요했다), (b) 어둡게 섞으면 카키가 되어 액센트를 한 색으로 묶어야 했다. 틸은 30%라 흰 면에서 UI 경계 기준(3:1)을 넘고 밝은 쪽으로 `#4FC4BF` `#94DBD7`을 뻗을 수 있다. 라임 전량 렌더본과 팔레트 스위처는 git 히스토리에 있다.

> **CTA 함정** — 섹션 배경이 `--bg-3`(포인트색)인데 `.btn--primary` 배경도 `--bg-3`이라 내비 버튼이 통째로 사라진다(1:1). `main.js`가 `on-point` 클래스를 붙이고 검정 알약으로 뒤집는다. 포인트색을 바꿀 때 반드시 다시 확인할 것.

### 4.1.1 phantom을 실측해서 뒤집은 통념

**색부터 바로잡았다.** phantom 페이지 픽셀을 직접 샘플링한 결과가 통념과 달랐다.

| 색상대 | 비중 | 대표색 |
|---|---|---|
| **보라 252°** | 4.09% | `#4A3893` `#5D46B8` `#9D90D4` `#BEB5E2` `#DEDAF0` |
| 하늘 216~228° | 1.44% | `#6B8FC6` `#90ABD4` |
| 크림 60° | 1.61% | `#F0F0DA` |
| **무채색** | **87.5%** | 검정·흰색·회색 |

**phantom은 색이 다양한 게 아니라 보라 하나를 명도 전 범위(L0.4~0.9)로 깔았다.** 카드가 라일락·크림·블랙으로 달라 보이는 건 명도 차이지 색상 차이가 아니다(크림 `#E6E4E0`은 채도 0.09로 사실상 무채색). 유채색은 화면의 12.5%뿐.

→ **브랜드 틸 `#0EA5A0`(2026-07-27 확정)을 깨지 않고 같은 효과를 낼 수 있다.** 틸 180°를 명도 램프로 전개하고, 보조 색상대는 Astryx neutral 테마(WCAG AA 검증됨)의 청록·하늘에서만 가져온다.

**틸 명도 램프** ([styles.css](../styles.css)):
`--t-08 #041817` · `--t-18 #05302E` · `--t-32 #0B5F5B` · **`--t-45 #0EA5A0`(브랜드)** · `--t-62 #4FC4BF` · `--t-78 #94DBD7` · `--t-90 #CFEDEB` · `--t-96 #E9F7F6`
보조: `--s-20 #00505F` · `--s-42 #3D6E80` · `--s-90 #E4EFF3`

**섹션별 배경 5색** — 스크롤에 명도 리듬을 준다. 히어로 `--t-96` → 정액무제한 `--t-90` → 주권 `--t-08`(검정 틸) → 신뢰·감사 `--s-90`(하늘빛) → CTA `--c-point`(브랜드).

### 4.2 hero — 실사 필름 「안 해도 되는 일」 (12.1초 · 2026-07-28)

**히어로는 UI가 아니라 사람의 하루다.** 제품 화면은 아래 카드 12장이 전담하고, 히어로는 헤드라인 한 문장만 증명한다. 실사와 UI 모션그래픽의 **대비**가 이 구조의 값어치다.

레퍼런스: [paraform.com](https://www.paraform.com) 히어로 (10.51초 · 11컷 · 평균 0.96초 · 배우가 연기하는 미니 서사 · 제품 화면 0프레임).

**서사 — 11컷 / 12.13초**

| 막 | 컷 | 내용 | 기기 |
|---|---|---|---|
| 1 파묻힘 | 1~4 | 야근 사무실 → 서류 더미 → 지친 얼굴 → 사무실 | — |
| 2 만들기 | 5~6 | 노트북 앞에서 **클릭 한 번** → 의자에 기댐 | **노트북** |
| 3 맡기기 | 7~8 | **폰을 집어 확인** → 안도하는 미소 | **핸드폰** |
| 4 해소 | 9~11 | 놀란 동료 → 자리에서 일어남 → 폰을 넣고 퇴근 | 핸드폰 |

헤드라인 「클릭으로 만들고(노트북), 메신저로 맡기는(폰)」이 2막 → 3막으로 흐른다. **기기 전환이 곧 유저플로우다.**

**촬영 원칙 (실패로 배운 것)**

1. **AI에게 UI를 그리게 하지 않는다.** 카드 12장을 폐기한 것과 같은 이유. 화면은 각도를 틀거나 아래로 기울여 **글로우만** 얼굴에 떨어지게 한다.
2. **정면을 향한 검은 화면을 쓰지 않는다.** "화면이 보이는 게" 문제가 아니라 "정면인데 꺼져 있는 게" 문제다. 정면 검정이 프레임의 15% 이상이면 그 구간은 버린다.
3. **기기만 나오는 컷을 쓰지 않는다.** 사람이 같은 프레임에 있어야 한다.
4. **무관한 컷을 넣지 않는다.** 레퍼런스에 있다고 시계·진자·머그를 가져오면 "여느 직장인의 아침"이 된다. 컷은 전부 서사에 기여해야 한다.
5. **타이핑을 보여주지 않는다.** 헤드라인이 「클릭으로」인데 열 손가락 타건을 보여주면 반증이 된다.

**모델·비용** — Google Veo 3.1 Lite, 4초당 **4크레딧**(Seedance 1.5 Pro의 1/3). 인물 컷 7개 재촬영에 28크레딧.

**톤** — paraform 히어로 실측(R93 G86 B67 · 채도 39.9%)에 맞춘 단일 그레이드. 현행 **R95 G85 B73 · 33.6%**. 프레임별 색온도(R−B) 표준편차 **6.7**로 컷 경계에서 튀지 않는다. 감정 전환은 색이 아니라 **조명과 공간**이 맡는다.

**노이즈** — 프롬프트에서 "필름 그레인"을 빼고 `hqdn3d` + `unsharp` + lanczos 업스케일. 중간 산출물 crf 16, 최종 mp4 crf 22 / webm crf 33.

**헤드라인은 영상 위에 얹지 않는다(A안, 2026-07-27 결정).** 영상 위에 헤드라인을 두면 콘텐츠와 자리를 다툰다 — 이전 콘솔 목업에서 실측 최소 명암비 **1.20:1**이었다. 스크림으로 덮는 건 자기모순이라 헤드라인을 위쪽에 따로 두고 영상은 아래 패널에 통째로 넣었다.

**보류 자산** — 이전 콘솔 목업 히어로는 `assets/video/hero-console.{mp4,webm,jpg}`로 남겨 뒀다. 히어로 방향이 확정되면 삭제한다.

> **미사용 코드** — `scenes.html`의 `SCENES['hero']`(추상 필름)·`SCENES['hero-slack']`·`SCENES['hero-notify']`(폰 화면 합성용)는 현재 사이트에서 쓰지 않는다. 기기 화면 합성 방식을 폐기하면서 남았다. 히어로 방향 확정 시 정리한다.

## 5. 렌더

```bash
# 1) 로컬 서버
python3 serve.py 8971

# 2) 프레임 캡처 (Playwright) — render(i/N)이라 마지막 다음이 정확히 i=0
#    scenes.html?scene=<이름>&w=<가로>&h=<세로>

# 3) 인코딩
ffmpeg -nostdin -framerate 30 -i frames/<이름>/%04d.png -an \
  -c:v libx264 -crf 26 -pix_fmt yuv420p -movflags +faststart assets/video/<이름>.mp4
ffmpeg -nostdin -framerate 30 -i frames/<이름>/%04d.png -an \
  -c:v libvpx-vp9 -crf 34 -b:v 0 -pix_fmt yuv420p assets/video/<이름>.webm
ffmpeg -nostdin -i frames/<이름>/0000.png -q:v 6 assets/video/<이름>.jpg   # 포스터 = 0프레임
```

- **fps 30**, 카드 **1048×1400**(3:4), 히어로 **1600×886**
- 포스터는 0프레임 그대로 → 재생 시작 순간 색이 튀지 않는다
- **`-nostdin` 필수.** 셸 루프에서 ffmpeg가 stdin을 먹어 루프가 중간에 끊긴다

## 6. 검증 — 눈으로 보지 말고 재라

### ① 루프 이음매

첫/끝 프레임 PSNR만 보면 **오판한다.** `render(i/N)`이라 마지막 프레임은 0프레임보다 정확히 한 프레임 앞이므로, 움직임이 빠른 장면은 낮게 나온다. 올바른 판정은 **이음매를 클립 내부의 일반 프레임 전환과 비교**하는 것이다. 이산 전환 카드(s1-1처럼 배지가 급변하는 구조)는 특히 그렇다 — 샘플이 정지 구간에 걸려 지표가 낮게 찍힌다.

현행 11장 실측 (이음매 / 내부 최악 전환):

| 장면 | 이음매 | 내부 최악 | 장면 | 이음매 | 내부 최악 |
|---|---|---|---|---|---|
| s1-1 | 99.0 | 12.3 | s3-1 | 99.0 | 14.4 |
| s1-2 | 99.0 | 12.7 | s3-2 | 93.5 | 11.1 |
| s1-3 | 99.0 | 12.4 | s3-3 | 99.0 | 10.7 |

99.0dB는 마지막 프레임과 0프레임이 픽셀 단위로 동일하다는 뜻이다. 되주차 설계의 결과다.

### ③ 모션 진폭

배경색과 다른 픽셀의 비율을 전 프레임에 걸쳐 잰다.

phantom 카드는 11~34%p 출렁인다. 잘림 금지 결정 이후 우리는 **1~26%p**로 떨어졌다(s1-2 26 · s3-4 14 · s3-3 5 · 나머지 1~4).

> **이 수치를 "정지 화면"으로 읽으면 안 된다.** 점유율은 *면적* 변화만 잰다. 라디오 선택이 옮겨가고 배지가 뜨고 템플릿 행이 통째로 갈리는 변화는 면적을 거의 안 바꾼다. 실제 프레임을 눈으로 대조해 확인했다 — 11장 모두 변화가 또렷하다. 면적 진폭이 필요하면 패널 축소 폭을 1.2%→3%로 키울 수 있다(경계 안, 넘침 0 유지). **미적용 — 소이님 확인 필요.**

### ④ 프레임 밖 넘침

`getBoundingClientRect()`로 전 요소를 훑어 무대(x 0~1048 · y 430~1400) 밖으로 나가는 것을 찾는다. 40프레임 전수. **11장 × 틸·라임 2팔레트 = 0건.**
